# מערכת להזמנת רכב משותף

מימוש של שלב א׳ (MVP) לפי מסמך האפיון (גרסה 1.0): הרשמה ואזור אישי, אישור משתמשים ורישיונות, יומן זמינות, בקשות הזמנה ואישור מנהל, מניעת הזמנות כפולות, מיילים אוטומטיים, ניהול נהלים, ניהול הרכב והרשאות.
הממשק בעברית, מימין לשמאל, ומותאם לטלפון ולמחשב.

## הפעלה

דרישות: Node.js 22.5 ומעלה (המערכת משתמשת ב־SQLite המובנה ב־Node, בלי שרת מסד נתונים נפרד).

```bash
npm install
npm run create-admin -- --email admin@example.org --password 'סיסמה-חזקה' --first דנה --last כהן --phone 0501234567
npm start            # http://localhost:3000
npm test             # בדיקות קצה לקצה
```

ללא הגדרת SMTP, המיילים לא נשלחים אלא נשמרים כקבצי `.eml` בתיקייה `data/outbox` (נוח לבדיקות).

### משתני סביבה

אפשר להגדיר אותם בקובץ `.env` (ראו `.env.example`), שנטען אוטומטית ב־`npm start`.

| משתנה | תיאור |
|---|---|
| `PORT` | פורט השרת (ברירת מחדל 3000) |
| `BASE_URL` | הכתובת הציבורית, משמשת לקישורים במיילים, למשל `https://car.example.org` |
| `NODE_ENV=production` | מפעיל עוגיות `Secure` ו־HSTS (חובה מאחורי HTTPS) |
| `DATA_DIR` | תיקיית הנתונים: מסד הנתונים, צילומי הרישיונות ו־outbox (ברירת מחדל `./data`) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS` | שרת דואר יוצא |
| `MAIL_FROM` | כתובת השולח |
| `APP_NAME` | שם המערכת שמוצג בממשק ובמיילים |

### העלאה לאוויר

- להריץ מאחורי reverse proxy עם HTTPS (Nginx/Caddy) או בפלטפורמה שמספקת HTTPS. השרת מוגדר עם `trust proxy`.
- **גיבוי:** כל הנתונים נמצאים ב־`DATA_DIR`. יש לגבות את התיקייה באופן תקופתי (למשל `sqlite3 app.db ".backup backup.db"` יחד עם תיקיית `licenses`).
- התיקייה `data/licenses` אינה נגישה ישירות מהרשת. הקבצים מוגשים רק דרך נתיב שבודק הרשאת מנהל, וכל צפייה נרשמת ביומן הפעולות.

## מבנה הקוד

```
src/
  server.js        אפליקציית Express, אבטחה (CSP, CSRF), העלאת קבצים
  config.js        הגדרות ומשתני סביבה (אזור זמן: Asia/Jerusalem)
  db.js            סכמת SQLite, הגדרות מערכת, נהלים
  bookings.js      כללי ההזמנה: חפיפות, זמן התארגנות, תוקף רישיון, מעברי סטטוס
  auth.js          סיסמאות (scrypt), סשנים, קוד חד־פעמי במייל, אימות דו־שלבי (TOTP)
  mail.js          כל תבניות המייל
  jobs.js          משימות רקע: סגירת הזמנות שהסתיימו, תזכורות, תוקף רישיונות
  routes/          public (הרשמה/התחברות), user (אזור אישי, יומן, הזמנות), admin (ממשק מנהל)
  views/           תבניות HTML (עם escaping אוטומטי) ויומן יום/שבוע/חודש
public/            CSS ו־JS (שיפורים בלבד: הכל עובד גם בלי JavaScript)
scripts/           create-admin
test/              בדיקות קצה לקצה
```

## החלטות ברירת מחדל לסעיף 13 (ניתן לשנות)

1. **רכב אחד.** מבנה הנתונים כבר תומך במספר רכבים (`vehicle_id` בכל הזמנה, סינון לפי רכב). חסר רק ממשק לבחירת רכב.
2. **הרשמה פתוחה לכולם**, וכל משתמש חדש דורש אישור מנהל.
3. **כל הזמנה דורשת אישור מנהל.** הזמנה ידנית של מנהל מאושרת מיד.
4. **ביטול עצמי:** בקשה ממתינה בכל עת, הזמנה מאושרת עד 24 שעות לפני תחילתה (ניתן לשנות בהגדרות).
5. **דיווח איסוף והחזרה** לא מומש (שלב ב׳). ההזמנה נסגרת אוטומטית כשמועד ההחזרה עבר.
6. **מגבלות:** עד 168 שעות להזמנה ועד 3 הזמנות פתוחות למשתמש (ניתן לשנות בהגדרות, 0 = ללא הגבלה).
7. **מספר מנהלים נתמך.** ניתן להפוך משתמש פעיל למנהל מכרטיס המשתמש. כל המנהלים מקבלים את התראות המייל.
8. **ללא חיובים ותשלומים.**
9. **אין בדיקת גיל או ותק.** ניתן להוסיף אם יידרש בהסדר הביטוחי.

## לא נכלל בשלב זה (שלב ב׳)

דיווח מצב הרכב באיסוף ובהחזרה (קילומטראז׳, דלק, תמונות), דוחות שימוש, ממשק לניהול מספר רכבים, SMS/WhatsApp, ניהול טיפולים מתקדם.

> **שימו לב:** הנהלים ומדיניות הפרטיות הם טיוטות. יש לעדכן אותם בהתאם להסדר הביטוחי ולייעוץ משפטי: את הנהלים דרך "נהלים" בממשק המנהל, ואת מדיניות הפרטיות בקובץ `src/routes/public.js`.
